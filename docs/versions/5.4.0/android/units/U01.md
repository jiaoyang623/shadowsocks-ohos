## Flows

### F-U01-01 Start the service from the main screen

1. **start**: start: the user taps the service button. Next: decision: can the current service state be stopped?
2. **decision**: decision: can the current service state be stopped? Decision exit: yes: the disconnect flow F-U01-02 runs.
3. **end**: yes: the disconnect flow F-U01-02 runs.
4. **step**: no: the service mode decides the start path. Next: decision: is the service mode VPN and does VpnService.prepare return a consent intent?
5. **decision**: decision: is the service mode VPN and does VpnService.prepare return a consent intent? Decision exit: yes: the system VPN consent dialog opens.
6. **step**: yes: the system VPN consent dialog opens. Next: decision: does the user allow the VPN?
7. **step**: no: the app starts the foreground service without a dialog, because the mode is not VPN or consent is already granted. Next: the service reports Connecting.
8. **decision**: decision: does the user allow the VPN? Decision exit: yes: the app starts the foreground service.
9. **step**: yes: the app starts the foreground service. Next: the service reports Connecting.
10. **end (exception exit)**: no: the user denies the VPN.
11. **step**: the service reports Connecting. Next: decision: did the core start?
12. **decision**: decision: did the core start? Decision exit: yes: the service reports Connected.
13. **step**: yes: the service reports Connected. Next: end: the button turns green and the stats bar shows the connection status.
14. **step (exception exit)**: no: the service reports Stopping and then Stopped with a message. Next: end: a snackbar shows the failure and the button returns to stopped.
15. **end**: end: the button turns green and the stats bar shows the connection status.
16. **end (exception exit)**: end: a snackbar shows the failure and the button returns to stopped.

Exception exits:

- The user denies the VPN consent: a snackbar reads Permission denied to create a VPN service and the state stays stopped.
- No profile is selected: the service stops at once and reports Please select a profile.
- The core cannot start: the service reports Stopping then Stopped with Failed to connect the remote server and the reason.

### F-U01-02 Stop the service from the main screen

1. **start**: start: the user taps the service button while state.canStop is true. Next: the activity broadcasts the CLOSE action.
2. **step**: the activity broadcasts the CLOSE action. Next: the service enters Stopping and the button shows the stopping icon.
3. **step**: the service enters Stopping and the button shows the stopping icon. Next: the service tears down processes, notification and receivers.
4. **step**: the service tears down processes, notification and receivers. Next: the service enters Stopped.
5. **step**: the service enters Stopped. Next: end: the button is enabled and shows the stopped icon; the stats bar hides.
6. **end**: end: the button is enabled and shows the stopped icon; the stats bar hides.

Exception exits:

- A stop request while already Stopping is ignored by stopRunner.
- A guarded process that exits within one second of starting stops the service without a user tap. A later exit is logged and the process restarts.

### F-U01-03 Open the drawer and switch content

1. **start**: start: the user taps the toolbar navigation icon. Next: the drawer opens from the start edge.
2. **step**: the drawer opens from the start edge. Next: the user selects a drawer item.
3. **step**: the user selects a drawer item. Next: decision: is the selected item already checked?
4. **decision**: decision: is the selected item already checked? Decision exit: yes: the drawer closes and the content stays.
5. **end**: yes: the drawer closes and the content stays.
6. **step**: no: the activity reads the selected item id. Next: decision: is the selected item the FAQ?
7. **decision**: decision: is the selected item the FAQ? Decision exit: yes: the FAQ URL opens in a custom tab.
8. **step**: yes: the FAQ URL opens in a custom tab. Next: end: the drawer stays open behind the custom tab and no item becomes checked.
9. **end**: end: the drawer stays open behind the custom tab and no item becomes checked.
10. **step**: no: the matching fragment replaces the content and the item is checked. Next: end: the drawer closes.
11. **end**: end: the drawer closes.

Exception exits:

- No activity can open the FAQ URL: a snackbar shows the URL instead and the drawer stays open.
- Selecting an unknown menu id returns false and leaves the drawer as it is.

### F-U01-04 Test the connection from the stats bar

1. **start**: start: the user taps the stats bar. Next: decision: is the state Connected?
2. **decision**: decision: is the state Connected? Decision exit: yes: the status becomes Testing.
3. **end (exception exit)**: no: no test starts.
4. **step**: yes: the status becomes Testing. Next: the app requests https://cp.cloudflare.com through the SOCKS proxy.
5. **step**: the app requests https://cp.cloudflare.com through the SOCKS proxy. Next: decision: is the response 204 or 200 with no body?
6. **decision**: decision: is the response 204 or 200 with no body? Decision exit: yes: the status shows Success with the elapsed time.
7. **step**: yes: the status shows Success with the elapsed time. Next: end: the status reads Success: HTTPS handshake took `<ms>`ms.
8. **end**: end: the status reads Success: HTTPS handshake took `<ms>`ms.
9. **step (exception exit)**: no: the status shows Internet Unavailable. Next: end: a snackbar shows the error code or the network message.
10. **end (exception exit)**: end: a snackbar shows the error code or the network message.

Exception exits:

- The request throws IOException: the status reads Internet Unavailable and the snackbar reads Fail to detect internet connection: `<message>`.
- Another test is requested while one runs: the running job is cancelled first.

### F-U01-05 Synchronize the UI with the bound service

1. **start**: start: the activity starts or the service mode changes. Next: the activity binds to the service class of the current mode.
2. **step**: the activity binds to the service class of the current mode. Next: decision: does the binder connect?
3. **decision**: decision: does the binder connect? Decision exit: yes: the reported state is rendered on the button and the stats bar.
4. **step**: yes: the reported state is rendered on the button and the stats bar. Next: end: the UI asks the service every 500 ms for a sample. The service broadcasts only a sample that changed or a rate that fell to zero, and that sample updates the bar.
5. **end**: end: the UI asks the service every 500 ms for a sample. The service broadcasts only a sample that changed or a rate that fell to zero, and that sample updates the bar.
6. **step (exception exit)**: no: the binder dies, so the activity disconnects and binds again; the framework's onServiceDisconnected may reset the UI to Idle. Next: the activity binds to the service class of the current mode.

Exception exits:

- A RemoteException while reading the state is treated as Idle.
- The unbind call throws IllegalArgumentException and is ignored.
- onServiceDisconnected renders Idle from any state. A binder death only disconnects and rebinds, so the Idle render depends on that separate callback.
- A service mode change drops the old binding and binds the new class. The new service reports its own state, so no Idle render is guaranteed.

### F-U01-06 Toggle the service from the keyboard

1. **start**: start: the user presses Ctrl+G with the main screen focused. Next: decision: can the current state stop the service?
2. **decision**: decision: can the current state stop the service? Decision exit: yes: the service stops through the CLOSE broadcast. no: the StartService contract runs because state.canStop is false.
3. **end**: yes: the service stops through the CLOSE broadcast.
4. **step**: no: the StartService contract runs because state.canStop is false. Next: decision: does the VPN consent dialog open?
5. **decision**: decision: does the VPN consent dialog open? Decision exit: yes: the system VPN consent dialog opens. no: the service receives the start command.
6. **step**: yes: the system VPN consent dialog opens. Next: the service receives the start command.
7. **step**: the service receives the start command. Next: decision: is the service state Stopped?
8. **decision**: decision: is the service state Stopped? Decision exit: yes: the start flow F-U01-01 runs. no: the service ignores the command because its state is not Stopped.
9. **end**: yes: the start flow F-U01-01 runs.
10. **end (exception exit)**: no: the service ignores the command because its state is not Stopped.

Exception exits:

- Ctrl+T runs the connection test even when the state is not Connected. No observer shows the result.
- Ctrl+G while the UI shows Idle launches the start contract. The service starts if its Data.state is Stopped, because Idle is a UI-only state.
- Ctrl+G while Connecting or Connected sends CLOSE and stops the service, because state.canStop is true. Ctrl+G while Stopping launches a start the service ignores, because its state is not Stopped.
- The user denies the VPN consent. No start command reaches the service.
