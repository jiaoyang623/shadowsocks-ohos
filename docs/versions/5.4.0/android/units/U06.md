## Flows

### F-U06-01 Open custom rules from the drawer

1. **start**: start: the user opens the navigation drawer.

5. **end**: the screen shows the rule list and the Add rule(s) menu.

### F-U06-02 Add one rule by hand

1. **start**: start: the user taps Add rule(s).
2. the user picks Manual Settings.
3. the dialog opens with the Generic template and an empty input.
4. the user picks a template and types the rule.
5. **decision**: decision: does the text pass the template check? Decision exits: Yes -> 6. No -> 12.
6. yes: the user taps OK.
7. **decision**: decision: is the Generic text empty? Decision exits: Yes -> 8. No -> 10.
8. yes: the empty rule is stored.
9. **end**: the empty rule appears in the list and reopening it shows no Remove button.
10. no: the rule is added and the list scrolls to it.
11. **end**: the rule appears in the list and the file is saved.
12. no: the dialog disables OK and shows the error.
13. the user fixes the text or taps Cancel.
14. **decision**: decision: does the fixed text pass the template check? Decision exits: Yes -> 6. No -> 15.
15. **end (exception exit)**: no: the list is unchanged.

Exception exits:
- Invalid text keeps OK disabled and shows the parse message.
- Cancel leaves the list unchanged.
- An empty Generic text is valid and stores an empty rule.

### F-U06-03 Edit an existing rule

1. **start**: start: the user taps a rule row with no selection.
2. the dialog opens with the matching template and the stored text.
3. the user changes the text.
4. **decision**: decision: which dialog button does the user press? Decision exits: Yes -> 5. No -> 8.
5. yes: the user taps OK.
6. the old rule is removed and the new rule is added.
7. **end**: the edited rule is in the list and the file is saved.
8. no: the user taps Remove or Cancel.
9. **decision**: decision: does the user remove or cancel? Decision exits: Yes -> 10. No -> 11.
10. **end**: yes: Remove deletes the rule with undo.
11. **end (exception exit)**: no: Cancel changes nothing.

Exception exits:
- Remove deletes the rule and shows Undo.
- Cancel changes nothing.
- A tap while a selection is active toggles selection and opens no dialog.

### F-U06-04 Import rules from the clipboard

1. **start**: start: the user taps Add rule(s) then Import from Clipboard.
2. the clipboard text is parsed as an ACL.
3. **decision**: decision: does the parse yield a proxy hostname, a proxy URL, or a subnet under a bypass default? Decision exits: Yes -> 4. No -> 7.
4. yes: the rows are added.
5. the list shows them.
6. **end**: the imported rules are in the list and the file is saved.
7. **end (exception exit)**: no: Failed to import.

Exception exits:
- The snackbar says Failed to import.
- A proxy_all text contributes no subnet: subnets are added only when the parsed default is bypass.

### F-U06-05 Import the GFW list

1. **start**: start: the user taps Add rule(s) then GFW List.
2. the gfwlist ACL file is read from noBackupFilesDir.
3. **decision**: decision: does the file hold any entry? Decision exits: Yes -> 4. No -> 6.
4. yes: add every entry.
5. **end**: the gfwlist entries are in the list.
6. **end (exception exit)**: no: nothing is added.

Exception exits:
- A missing or empty gfwlist file leaves the list unchanged and reports nothing.
- The file in noBackupFilesDir is the bundled copy or the AclSyncer copy, whichever is there.

### F-U06-06 Delete one rule by swipe and undo

1. **start**: start: the user swipes a row toward the start.
2. **decision**: decision: does the swipe gate allow editing and is the selection empty? Decision exits: Yes -> 3. No -> 8.
3. yes: the row is removed.
4. the undo snackbar appears.
5. **decision**: decision: does the user tap Undo before the snackbar ends? Decision exits: Yes -> 6. No -> 7.
6. **end**: yes: the rule comes back.
7. **end (exception exit)**: no: the removal stays.
8. **end (exception exit)**: no: the row springs back.

Exception exits:
- The removal stays when the snackbar is dismissed.
- A swipe does nothing while the swipe gate is blocked or a selection is active.
- A second removal before the snackbar ends reports the combined count.

### F-U06-07 Multi-select copy, cut, or remove

1. **start**: start: the user long presses a row.
2. the action mode shows Select all, Cut, Copy, Remove.
3. the user adds or removes rows from the selection.
4. **decision**: decision: does the user press Back? Decision exits: Yes -> 16. No -> 5.
5. **decision**: decision: copy or destructive action? Decision exits: Yes -> 6. No -> 10.
6. yes: Copy.
7. **decision**: decision: does the clipboard write succeed? Decision exits: Yes -> 8. No -> 9.
8. **end**: yes: Successfully export.
9. **end (exception exit)**: no: Failed to export.
10. no: Cut or Remove.
11. **decision**: decision: is the action Cut? Decision exits: Yes -> 12. No -> 13.
12. yes: Cut copies and then removes the selection whatever the copy result. Next: 14.
13. no: Remove removes the selection.
14. the selected rules leave the list and the undo snackbar appears.
15. **end**: the rules are gone and the undo snackbar offers them back.
16. **end (exception exit)**: Back ends the action mode and keeps the rules.

Exception exits:
- A failed clipboard write shows Failed to export. Cut still removes its selection.
- Back ends the action mode and keeps the rules.

### F-U06-08 Connect with the custom-rules route

1. **start**: start: the user connects a profile whose route is custom-rules.
2. the service reads custom-rules-user.acl through the forced-bypass getter.
3. the getter forces the default to bypass and drops the subnets when the file said proxy_all.
4. **decision**: decision: does the file have import URLs? Decision exits: Yes -> 5. No -> 7.
5. yes: the importer fetches and flattens them ten deep.
6. **decision**: decision: does every fetch succeed? Decision exits: Yes -> 8. No -> 11.
7. no: the importer has nothing to fetch and saves the getter result.
8. save custom-rules.acl.
9. the core starts with custom-rules.acl passed as --acl.
10. **end**: the tunnel connects with the custom rules applied.
11. **end (exception exit)**: the start fails.

Exception exits:
- An IO error during flattening fails the start with the service-failed message.
- A malformed IMPORT_URL line throws MalformedURLException and fails the start the same way.
- The core never reads custom-rules-user.acl. It is always given custom-rules.acl.

### F-U06-09 Refresh a preset ACL in the background

1. **start**: start: the proxy instance starts a route other than all and custom-rules.
2. the sync worker is scheduled for that route.
3. **decision**: decision: is the user unlocked and the route eligible? Decision exits: Yes -> 4. No -> 11.
4. yes: the work is enqueued with REPLACE, unmetered and charging constraints, and a ten second delay.
5. the worker downloads `https://shadowsocks.org/acl/android/v1/<route>.acl`.
6. **decision**: decision: did the download succeed? Decision exits: Yes -> 7. No -> 9.
7. yes: the copy replaces `<route>.acl`.
8. **end**: the route ACL file holds the refreshed copy.
9. retry until more than five attempts have failed.
10. **end (exception exit)**: the work fails after more than five attempts.
11. **end (exception exit)**: no work is enqueued.

Exception exits:
- Schedule returns without work while the user is locked.
- A download that keeps throwing IOException fails after more than five attempts.

### F-U06-10 Deploy the preset ACL files

1. **start**: start: the app starts after an update, or a route other than all is used.
2. **decision**: decision: does the package update time differ from the stored asset time? Decision exits: Yes -> 3. No -> 4.
3. yes: copy every bundled ACL asset to noBackupFilesDir. Next: 5.
4. no: keep the files on disk.
5. the route ACL file exists in noBackupFilesDir.
6. **decision**: decision: is the route all? Decision exits: Yes -> 7. No -> 8.
7. **end**: the core starts with no --acl argument.
8. **end**: the core starts with `--acl <noBackupFilesDir>/<route>.acl`.

Exception exits:
- An IOException during the asset copy is logged and the stored asset time is still saved.
- The gfwlist file may later be replaced by the AclSyncer copy.
