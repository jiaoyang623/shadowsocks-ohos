## Flows

### F-U11-01 Ongoing notification appears and tracks traffic

1. **start**: Service: starts with the current profile and creates ServiceNotification. Next: 2.
2. **step**: ServiceNotification: posts the notification before connecting. Next: 3.
3. **decision**: Is the screen interactive at creation? Decision exits: Yes -> 4. No -> 7.
4. **step**: Yes: register the traffic callback. Next: 5.
5. **step**: A traffic sample arrives every second while Connected. Next: 6.
6. **step**: ServiceNotification: rewrites content text to rates and subtext to totals. Next: 8.
7. **step**: No: post without a callback. Next: 9.
8. **end**: Live rates and totals shown.
9. **end**: Only the profile name is shown until a screen-on while Connected.

Exception exits:
- The service stops. ServiceNotification.destroy unregisters the receiver, unsubscribes and removes the notification.
- A traffic sample with a profile id other than 0 is ignored, so only the summed sample is shown.
- A start without a profile posts an empty-name notification, then stops with Please select a profile.

### F-U11-02 Stop the service from the notification

1. **start**: User: opens the notification shade while the service runs. Next: 2.
2. **step**: User: activates Stop. Next: 3.
3. **step**: System: sends the app-scoped Action.CLOSE broadcast. Next: 4.
4. **decision**: Is the service already Stopping? Decision exits: Yes -> 7. No -> 5.
5. **step**: No: stopRunner changes the state to Stopping. Next: 6.
6. **step**: BaseService: shuts down proxies and destroys the notification. Next: 8.
7. **step**: Yes: ignore the duplicate stop. Next: 9.
8. **end**: The service is Stopped and the notification is removed.
9. **end**: The notification keeps its last state.

Exception exits:
- The Action.CLOSE broadcast is package-scoped, and ContextCompat registers the receiver with RECEIVER_NOT_EXPORTED, which only takes effect from API 33. On earlier releases another app can send the same action to this package and stop the tunnel.
- A stop while Connecting cancels the connecting job first.
- The action requires authentication, so a locked device blocks it until unlock.

### F-U11-03 Open the app from the notification body

1. **start**: User: taps the notification body. Next: 2.
2. **step**: System: fires the configure PendingIntent. Next: 3.
3. **end**: MainActivity: comes to the front with FLAG_ACTIVITY_REORDER_TO_FRONT.

### F-U11-11 Fire a Tasker action setting

1. **start**: Tasker: sends FIRE_SETTING to ActionListener. Next: 2.
2. **step**: ActionListener: reads switch_on and profile_id. Next: 3.
3. **decision**: Does the profile exist? Decision exits: Yes -> 4. No -> 5.
4. **step**: Yes: switch profile. Next: 6.
5. **step**: No: keep the current profile. Next: 6.
6. **decision**: Is switch_on set? Decision exits: Yes -> 7. No -> 11.
7. **step**: Yes: start the service. Next: 8.
8. **decision**: Was a stored profile found? Decision exits: Yes -> 9. No -> 10.
9. **step**: Yes: reload the service. Next: 12.
10. **step**: No: done. Next: 13.
11. **step**: No: stop the service. Next: 14.
12. **end**: The service restarts on the stored profile.
13. **end**: The service starts or keeps running on the current profile.
14. **end**: The service stops.

Exception exits:
- The stored profile was deleted: the old profile stays selected, the switch still starts or stops the service, and no reload runs.
- A fire that names the already-selected profile still reloads, because changed is set whenever the stored profile exists.
