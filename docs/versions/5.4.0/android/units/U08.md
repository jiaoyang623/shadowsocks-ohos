### F-U08-01 Select a plugin from the picker

1. **start**: User: opens a profile in Profile config. Next: 2.
2. **step**: System: shows the Plugin row with the current plugin label and icon. Next: 3.
3. **step**: User: taps the Plugin row. Next: 4.
4. **step**: System: opens the plugin bottom sheet with Disabled and every installed plugin. Next: 5.
5. **decision**: Is the current value a known plugin? Decision exits: Yes -> 6. No -> 7.
6. **step**: Yes: the current plugin moves to the first row and its label is bold. Next: 8.
7. **step**: No: the list keeps discovery order. Next: 8.
8. **step**: User: taps a row, dismisses the sheet, or long-presses a row. Next: 9.
9. **decision**: Did the actor tap a row? Decision exits: Yes -> 10. No -> 11.
10. **step**: Yes: the tapped row is compared with the current value. Next: 15.
11. **decision**: Was the row long-pressed? Decision exits: Long-press -> 12. Dismiss -> 13.
12. **step**: Long-press: the app info screen opens, or the press returns false when no activity handles it. Next: 14.
13. **end**: Dismiss: the sheet closes with no result.
14. **end**: System: the picker is shown again.
15. **decision**: Is the tapped row the current value? Decision exits: Yes -> 16. No -> 17.
16. **end**: Yes: no result is sent.
17. **step**: No: the id is sent to the editor. Next: 18.
18. **step**: System: stores the plugin, its options and the dirty flag. Next: 19.
19. **step**: System: the summary and Configure… update. Next: 20.
20. **decision**: Is the plugin trusted? Decision exits: Yes -> 21. No -> 22.
21. **end**: Yes: the selection is complete.
22. **end**: No: the warning snackbar appears after the row updates.

Exception exits:
- The plugin package is removed while the sheet is open. The next package broadcast rebuilds the list. A row bound from the old list then sends an id that the new lookup does not contain, and the result listener throws NoSuchElementException. Without a tap the row refreshes to Unknown plugin.
- Two providers declare the same plugin id or alias. A toast names the packages that share the later plugin's id, and PluginList throws IllegalStateException.
- The system has no activity for application details. The long press returns false and the sheet stays open.

### F-U08-02 Edit options in the built-in editor

1. **start**: User: taps Configure… with a known plugin selected. Next: 2.
2. **decision**: Does ACTION_CONFIGURE resolve? Decision exits: Yes -> F-U08-03. No -> 3.
3. **step**: System: opens the options dialog titled Configure… with the stored options in a monospace field. Next: 4.
4. **decision**: Does ACTION_HELP resolve? Decision exits: Yes -> 5. No -> 6.
5. **step**: System: shows the ? neutral button. Next: 7.
6. **step**: No: the ? neutral button is absent. Next: 7.
7. **step**: User: edits the options and taps OK, Cancel, or ?. Next: 8.
8. **decision**: Which button? Decision exits: OK -> 12. Cancel -> 9. ? -> 10.
9. **end**: Cancel: the dialog closes with no change.
10. **end**: ?: the options dialog is dismissed, the edit is discarded, and plugin help opens (F-U08-06).
11. **end**: Dismiss: the dialog is closed by back or an outside tap and the edit is discarded.
12. **step**: System: parses the text as SIP003 options. Next: 13.
13. **decision**: Does the text contain a control character? Decision exits: Yes -> 14. No -> 15.
14. **end (exception exit)**: Yes: the error snackbar shows and the change is refused.
15. **step**: System: stores the options and marks the profile dirty. Next: 16.
16. **end**: System: updates the Configure… summary.

Exception exits:
- A trailing backslash consumes the appended terminator. The last key/value pair is dropped, no exception is thrown, and the change is accepted with that pair missing.
- Any RuntimeException from the change listener refuses the change and shows its message.

### F-U08-03 Configure through the plugin's own configuration activity

1. **start**: User: taps Configure… and ACTION_CONFIGURE resolves. Next: 2.
2. **step**: System: launches the plugin activity with `plugin://com.github.shadowsocks/<id>` and EXTRA_OPTIONS. Next: 3.
3. **step**: User: edits the options in the plugin screen. Next: 4.
4. **decision**: Result code? Decision exits: RESULT_OK -> 5. RESULT_FALLBACK -> 13. RESULT_CANCELED -> 15.
5. **step**: System: reads EXTRA_OPTIONS (null when the result carries none) and applies it. Next: 6.
6. **decision**: Does the result carry EXTRA_OPTIONS? Decision exits: Yes -> 7. No -> 10.
7. **step**: Yes: the returned text is parsed. Next: 8.
8. **decision**: Do the options parse? Decision exits: Yes -> 9. No -> 12.
9. **step**: Yes: the options are stored. Next: 11.
10. **end**: No: RESULT_OK without EXTRA_OPTIONS clears the stored options.
11. **end**: System: stores the options and updates the Configure… row.
12. **end (exception exit)**: No: the error snackbar shows and nothing is stored.
13. **step**: RESULT_FALLBACK: the built-in editor opens. Next: 14.
14. **end**: System: the editor shows the stored options.
15. **end**: RESULT_CANCELED: nothing changes.

Exception exits:
- The configuration activity crashes or never returns. The result is treated as canceled and the options stay.
- The activity is missing even though resolveActivity succeeded. The launch throws and no result arrives.

### F-U08-04 Discover plugins and refresh after a package change

1. **start**: System: fetchPlugins is called for the first time. Next: 2.
2. **step**: System: builds PluginList from exported native plugin providers. Next: 3.
3. **decision**: Duplicate id or alias? Decision exits: Yes -> 4. No -> 5.
4. **end (exception exit)**: Yes: a toast names the packages that share the later plugin's id and IllegalStateException is thrown.
5. **step**: System: the list is cached and returned. Next: 6.
6. **step**: System: the picker shows Disabled and the cached plugins. Next: 7.
7. **decision**: Did a package get installed or removed? Decision exits: Yes -> 8. No -> 9.
8. **step**: Yes: clears the cache and re-inits the plugin rows. Next: 10.
9. **end**: No: the cache is reused.
10. **end**: System: the next fetch rebuilds the list.

Exception exits:
- A provider without the plugin id metadata throws a NullPointerException while the list is built.

### F-U08-05 Start a session with the selected plugin

1. **start**: User: connects a profile. Next: 2.
2. **step**: System: reads the stored plugin string. Next: 3.
3. **decision**: Is the plugin id empty? Decision exits: Yes -> 4. No -> 6.
4. **step**: Yes: the core runs without a plugin. Next: 5.
5. **end**: System: the tunnel starts directly.
6. **step**: No: the provider is queried for `plugin://com.github.shadowsocks/<id>`. Next: 7.
7. **decision**: How many providers match? Decision exits: None -> 8. Many -> 9. One -> 12.
8. **step**: None: PluginNotFoundException is thrown. Next: 10.
9. **step**: Many: a toast names the packages and IllegalStateException is thrown. Next: 10.
10. **step (exception exit)**: System: the service stops with the message. Next: 11.
11. **end (exception exit)**: System: a snackbar reports the failure.
12. **step**: System: loads the entry path and the options, filling absent options from default_config. Next: 13.
13. **decision**: Does the UDP fallback profile carry a plugin? Decision exits: Yes -> 14. No -> 15.
14. **end (exception exit)**: Yes: the start fails with UDP fallback cannot have plugins.
15. **end**: System: starts the core with plugin and plugin_opts in tcp_only mode.

Exception exits:
- The plugin executable cannot run. The start fails and the service reports the message.
- UDP through a SIP003 plugin times out because neither built-in plugin carries UDP.

### F-U08-06 Ask the plugin for help

1. **start**: User: taps ? in the options editor, which dismisses the editor and discards the typed edit. Next: 2.
2. **step**: System: launches ACTION_HELP with `plugin://com.github.shadowsocks/<id>` and EXTRA_OPTIONS. Next: 3.
3. **decision**: What does the help activity return? Decision exits: RESULT_OK -> 4. RESULT_CANCELED or a visible screen -> 6.
4. **step**: System: an alert titled ? shows the help message, empty when the extra is absent. Next: 5.
5. **end**: User: dismisses the alert.
6. **end**: RESULT_CANCELED or a visible help screen: no alert appears.

Exception exits:
- The plugin declares no help activity. The ? button is never added to the editor.
- The help activity crashes. The result is treated as canceled.
