# HarmonyOS 5.4.0 requirements for Android mobile parity

Sections: 用户、问题与结果、Scope、需求条目、Lifecycle、未决项.

This document is the requirement set for the HarmonyOS 5.4.0 parity release. It follows the a01 requirements-layer contract (L-01-a). The source is the Android mobile module at tag v5.3.5-nightly, commit ae28fd9.

## 用户

Users of the system.

1. Phone user: runs Shadowsocks on a HarmonyOS NEXT phone. This person adds a server, picks a route, connects, checks traffic, and manages subscriptions.
2. HarmonyOS developer: ports the Android behavior to the HarmonyOS app. This person reads the control tree, the requirements, and the E2E cases.

### U-USER: Phone user

A person who runs Shadowsocks on a HarmonyOS NEXT phone. This person adds a server, picks a route, connects, checks traffic, and manages subscriptions.

### U-DEV: HarmonyOS developer

A developer who ports the Android behavior to the HarmonyOS app. This person reads the control tree, the requirements, and the E2E cases.

## 问题与结果 (Problem and outcome)

**Problem.** The HarmonyOS app is a separate implementation. Android behavior changes do not reach it automatically. No verified list maps each Android screen and control to a HarmonyOS behavior.

**Outcome.** A verified control tree, a requirement set, and an E2E case set describe the Android mobile app at the pinned baseline. Each item states its current HarmonyOS parity.

## Scope

### In scope

- Every page, dialog, menu, and preference screen in the Android mobile module.
- Every control that a user can see or operate.
- Behavior that the UI exposes, including state changes and validation.
- A parity tag for each requirement and each E2E case.

### Out of scope

- Android TV module behavior.
- Plugin APK internals beyond the UI contract.
- Network protocol internals that the UI does not expose.
- HarmonyOS implementation work in this version.

### Later

- The a01 requirements model and review batch.
- HarmonyOS implementation and UI restoration checks.
