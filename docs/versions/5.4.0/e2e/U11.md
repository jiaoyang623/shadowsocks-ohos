### TC-U11-26 Shutdown counters survive in the device profile and flush after unlock

- Preconditions:
  - Direct boot is on and the device profile copy exists.
  - The service is running while the device is locked.
- Steps:
  1. Send ACTION_SHUTDOWN.
  2. Reboot and unlock the device.
- Expected:
  1. The close receiver calls persistStats. The credential-encrypted database is unreachable, so the counters go into the device profile, the profile gets the dirty flag and DirectBoot.listenForUnlock registers for ACTION_BOOT_COMPLETED.
  2. After unlock, the ACTION_BOOT_COMPLETED receiver that listenForUnlock registered calls DirectBoot.flushTrafficStats. If the process starts after the unlock instead, Core.init runs the same flush.
  3. The database profile gets the counters and the device copy is refreshed.
- Control path: `C-U11-001`
- HarmonyOS parity: android-only
- Android source: `core/src/main/java/com/github/shadowsocks/bg/BaseService.kt:94`

### TC-U11-27 Screen events during Connecting do not change the traffic subscription

- Preconditions:
  - The VPN service is Connecting to a server that takes a few seconds to answer.
  - The screen is on when the service starts.
- Steps:
  1. Turn the screen off before the state becomes Connected.
  2. Let the service connect and send traffic.
  3. Stop the service, turn the screen off, start it again, and turn the screen on before the state becomes Connected.
- Expected:
  1. ServiceNotification.onReceive ignores the screen-off because the state is not Connected, so the callback stays registered.
  2. The notification shows live rates although the screen is off.
  3. The start with the screen off registers no callback, and the screen-on while Connecting is ignored, so the notification shows no rates for that session.
- Control path: `C-U11-001 > C-U11-004`
- HarmonyOS parity: partial
- Android source: `core/src/main/java/com/github/shadowsocks/bg/ServiceNotification.kt:104`

### TC-U11-28 Each boot action starts only in its own direct boot mode

- Preconditions:
  - Auto Connect is on and BootReceiver.enabled is true.
  - A valid profile named Tokyo is selected.
  - The device runs API 24 or later with per-user encryption.
- Steps:
  1. Turn Allow Toggling in Lock Screen off. Send BOOT_COMPLETED.
  2. Stop the service. Send LOCKED_BOOT_COMPLETED with direct boot still off.
  3. Turn Allow Toggling in Lock Screen on. Reboot into the locked state. Let LOCKED_BOOT_COMPLETED arrive.
  4. Unlock the device. Let BOOT_COMPLETED arrive.
  5. Stop the service. Send MY_PACKAGE_REPLACED while the user is unlocked.
- Expected:
  1. The receiver starts the service. The notification content title shows Tokyo.
  2. No service starts. No notification is posted. DataStore.directBootAware is false, so LOCKED_BOOT_COMPLETED does not start the service.
  3. The receiver starts the service from the device-protected profile. The notification content title shows Tokyo.
  4. The receiver does not start the service again on BOOT_COMPLETED. Direct boot is on, so the service stays as it is.
  5. The receiver starts the service. Direct boot is on and the user is unlocked.
- Control path: `C-U11-001 > C-U11-003`
- HarmonyOS parity: android-only
- Android source: `core/src/main/java/com/github/shadowsocks/BootReceiver.kt:48`
